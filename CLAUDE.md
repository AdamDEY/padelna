# Padelna

Padelna is a social app for padel players: find and create matches at the right level, book courts, rate players and confirm scores. A player's level (1–7 scale) and trust signals (confirmed scores, reputation) are the core of the product. Launch market is Tunisia (`+216` phone numbers); the UI ships in English first, with French and Arabic (right-to-left) planned.

## Stack

- Expo SDK 58, React Native 0.88, React 19, TypeScript (strict), Expo Router (typed routes)
- **HeroUI Native** (`heroui-native`) for UI components, styled with **Uniwind** (Tailwind CSS v4 for React Native)
- Reanimated 4, Gesture Handler 3, `@gorhom/bottom-sheet`
- Package manager: **npm** (`package-lock.json`). Use `npx`, and `npx expo install <pkg>` to add packages.
- iOS and Android only. HeroUI Native is not supported on web, so don't build or test for web.

## Commands

```bash
npm run ios                 # native build + run on the iOS Simulator (needed after any native dependency change)
npx expo start --dev-client # start Metro for an existing dev build
npx expo start --dev-client --clear  # after changing metro.config.js or when styles look stale
npx tsc --noEmit            # typecheck
npx expo lint               # lint
```

This is a development build, not Expo Go. CocoaPods needs a UTF-8 locale (`LANG=en_US.UTF-8`, already set in `~/.zshrc`).

## Project layout

- `src/app/` — routes only (Expo Router). Every file is a screen; `_layout.tsx` files are navigators.
- `src/components/` — shared components, built on top of HeroUI components.
- `src/global.css` — Tailwind/Uniwind/HeroUI entry and **the single place where design tokens live** (as HeroUI theme variables).
- `src/uniwind-types.d.ts` — generated by Uniwind when Metro starts; don't edit by hand.
- `example/` — the old Expo template, git-ignored and excluded from typecheck. Use it for reference only; never import from it.
- `ios/` — generated (CNG). Configure native behaviour in `app.json` / config plugins instead.
- Import from `src` with the `@/` alias (`@/components/...`).

## UI rules

`design.md` is the source of truth for colours, type, spacing, radii and component specs. HeroUI provides the components. Combine them like this:

1. **Use a HeroUI component first.** Before building any control (button, input, chip, card, segmented control, bottom sheet, dialog, avatar, toast, etc.), check whether HeroUI Native has it and use it, styled to match `design.md`. Only build a custom component when HeroUI has nothing suitable (e.g. level chip, score grid, court placeholder), and put it in `src/components/`.
2. **Style with Uniwind `className`**, not `StyleSheet.create` or inline style objects. Inline styles are fine only for dynamic values (animations, computed sizes).
3. **Never hard-code hex colours in components.** Map `design.md` colours onto HeroUI's theme variables in `src/global.css` (`--background`, `--surface`, `--foreground`, `--accent`, `--success`, `--warning`, `--danger`, `--border`, `--field-*`, …). Add Padelna-only colours (lime, attention, avatar tints, …) as new variables plus `@theme inline` mappings, so they can be used as Tailwind classes (`bg-lime-soft`, `text-ink-2`).
4. **Light theme only** for now. `design.md` defines no dark palette, so don't add `dark:` variants.
5. **Font is Nunito** (400, 600, 700, 800, 900), set through HeroUI's `--font-*` variables. Hierarchy comes from weight (800–900), not from extra colours.
6. **Spacing and radii** follow the `design.md` scale: 20 px screen margins (24 px on auth/setup/onboarding), cards with radius 20–24 and padding 14–16, inputs 52 px tall with radius 14, primary buttons 54–56 px tall with radius 16–18.
7. **One primary (blue) button per screen**, usually pinned 34 px from the bottom.
8. **No gradients, emoji or card shadows.** Shadows are only for floating elements (FAB, the centre Create button).
9. **Icons** are outline style, 24 px grid, 1.8 px stroke (Lucide-style).
10. **Main tabs use the native iOS tab bar** (Expo Router native tabs). Don't recreate the Liquid Glass look by hand.

## Accessibility and copy

- Touch targets at least 44 px. Body text never below 13 px, labels never below 11 px.
- Every input has a visible label. Icon-only buttons get an `accessibilityLabel`.
- Colour is never the only signal: selected states add a border or tick, warnings add an icon, wins/losses add W/L.
- Keep text out of images and leave room for longer French words. Prefer `start`/`end` (`ps-*`, `pe-*`, `ms-*`, `me-*`) over `left`/`right` so layouts flip for Arabic.
- Copy is short, warm and direct ("Let's play", "Book your court first"). Don't call a level "Verified" until coach verification exists.
